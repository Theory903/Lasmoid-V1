DESIGN Architecture & design concerns ▼
MLA uses a single shared KV projection (wkv) — not true MLA
Real MLA (as in DeepSeek-V2) uses separate wkv_a (down-projection to latent) and wkv_b (up-projection to full KV per head). This implementation compresses to a single head_dim vector and uses it as K=V for all heads simultaneously. This is closer to Multi-Query Attention (MQA) with a shared key-value, not MLA.
model.py:304-349
ElasticSparseConceptMemory: n_heads=8 hardcoded — breaks if dim is not divisible by 8
Line 537: n_heads = 8 is hardcoded inside process_chunk. If dim=128 this gives head_dim=16, which works. But any dim not divisible by 8 (e.g. dim=96) silently produces a wrong reshape without an error until the view call fails.
n_heads = 8 # hardcoded — should be a ModelArgs parameter
model.py:537
Elastic spawn recursion can stack-overflow with high entropy — no depth guard
process_chunk calls itself recursively when loss > entropy_threshold (line 604). In early training when all losses are high, this will recurse until max_blocks is hit. But if the recursive call itself triggers another spawn before max_blocks is checked, the ModuleList could grow unboundedly before the guard fires. Also, Python recursion limit is 1000.
model.py:571-604
generate.py: batch generation processes prompts serially — no actual batching
The generate() function loops over prompt_tokens one at a time (line 256: for tokens_list in prompt_tokens). Each prompt does a separate forward pass. The max_batch_size parameter in ModelArgs is therefore meaningless in inference — no speedup from batching.
